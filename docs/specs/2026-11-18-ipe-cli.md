# InPageEdit CLI

## 目标

让 agent 在终端以明确的 Wiki 和 bot 身份读取、创建及编辑 MediaWiki 页面。首次配置和凭据更新由用户直接完成。

## 范围

- 独立的 `@inpageedit/cli` 包提供 `ipe` 命令，使用 `wiki-saikou` 的 Node 客户端。IPE 浏览器核心的拆分留待后续。
- 支持 profile 列表及默认 profile 切换、身份查询、页面搜索、读取源码、创建、覆盖编辑、移动、上传本地文件以及通用 Action API 请求。
- 分段读写、读取到本地文件、与线上版本的差异、保存前预览，以及随版本发布、由 `ipe skill` 打印的 agent 使用指南。
- 不含：主账号登录（只支持 Bot Password）、批量编辑、列表生成器、回退与删除等管理命令。

## 决策

1. 每个 profile 存放一个明确的 Action API 地址和 MediaWiki 账号。默认 profile 用于交互，`--profile` 为当次命令指定身份，便于 agent 并行操作。
2. 终端隐藏输入与一次性本地网页使用同一种 MediaWiki Bot Password。agent 可以预填 profile 名称、API 地址与 Bot Password 登录名。网页说明如何在 `Special:BotPasswords` 获取这两项，用户点击保存后 CLI 验证身份并保存 profile。
3. 配置目录默认为 `~/.config/inpageedit/`，可用 `IPE_CONFIG_DIR` 覆盖。Profile 文件保存 API 地址和账号信息。Bot Password 存入 macOS 钥匙串、Windows 凭据管理器或 Linux Secret Service。密码输入经过用户的终端或浏览器直接交给 CLI，命令行参数、输出和配置文件只处理非秘密数据。
4. 登录网页仅监听 loopback，采用随机会话路径，保存后关闭。每个 profile 在系统凭据库缓存独立的登录 Cookie，供不同 CLI 进程复用。Wiki 操作通过 `assert=user` 和 `assertuser` 校验身份。缓存缺失或登录状态被服务端拒绝时，用已保存的 Bot Password 登录一次。只有服务端在执行操作前明确拒绝认证或读权限时，才用新会话重试原操作。替换内容必须带原 revision ID，创建使用 MediaWiki 的 create-only 约束。
5. `--json` 在标准输出返回结果，在标准错误返回可识别的错误码。缺少或失效的凭据返回 `login_required` 和用户可运行的登录命令。

6. `action-api` 支持 GET、POST、重复的 `--query key=value` 和 `--form key=value`、`--form field=@path` 本地附件以及从 JSON 文件或 stdin 读取的 `--body` 字段。CLI 向当前 profile 的 API 发送请求，设置身份断言，并按 `--token csrf` 获取令牌。成功响应保留 MediaWiki JSON 数据结构。
7. `page move` 要求理由，默认保留重定向，可显式控制讨论页和重定向。讨论页移动失败时返回 Wiki 的警告。
8. `file upload` 默认使用本地文件名，支持指定 Wiki 文件名、摘要和描述文件。上传警告通过非零退出码与结构化错误返回，用户可以用 `--ignore-warnings` 确认继续。
9. `page get`、`page search` 和不带 `--token` 的 `action-api` 可以用 `--api URL` 代替 profile 匿名读取，不读凭据库，权限以 Wiki 对匿名用户的设置为准。`--api` 不能与 `--profile`、`--token` 同用。
10. 凭据库调用在 worker 线程中执行。macOS 在其他程序读取已保存的凭据时会弹出授权窗口并阻塞调用，3 秒未返回时向 stderr 输出提示（`--json` 下为 `credential_prompt` 事件），60 秒后以 `credential_store_timeout` 退出。
11. MediaWiki 错误保留服务端的错误文本。不是普通标识符的错误码（如扩展抛出的 `internal_api_error_<类名>`）报为 `mediawiki_error`，原始错误码放在 `apiCode`。网络层错误只报告错误码和 HTTP 状态，不输出请求内容。
12. 源码使用 TypeScript，由 `tsc` 编译到 `dist`，`ipe` 指向编译产物，依赖不打包。
    Why：仓库其他包都是 TS；CLI 只在 Node 运行，用不着 vite 打包。
13. `page get --section N` 读取第 N 段（0 为导言），`page edit --section N` 只替换该段，仍须带 `--base-revid`。只接受非负整数。
    Why：长条目整页读写费 token，且容易误改其他段落。
14. `page get --out FILE` 把源码原样写入文件，标准输出只给元数据（标题、revision ID、段号、文件路径）。
    Why：agent 的推荐流程是下载到临时目录、用自己的编辑工具修改、再以 `--file` 提交；从 JSON 里取正文再落盘容易被 shell 转义破坏。
15. `page diff TITLE --file PATH [--section N] [--base-revid ID]` 在本地生成本地文件与线上版本（默认最新版本，或指定版本）的 unified diff，JSON 输出附带比较所用的 revision ID。
    Why：本地 diff 不依赖 Wiki 的 compare 接口和 HTML 输出，终端和 agent 都能直接读。
16. `page preview TITLE --file PATH` 用 `action=parse`（含签名展开等保存时转换）解析本地源码，输出解析警告、分类、缺失的模板和红链；`--html PATH` 另存完整渲染结果供人打开。
    Why：保存前发现模板错误、错误分类和红链，渲染 HTML 本身在终端里没法读。
17. `page get`、`page search`、`page diff`、`page preview` 和不带 `--token` 的 `action-api` 都可以用 `--api` 匿名执行。
18. agent 使用指南随包发布，`ipe skill` 原样打印。它讲方法而不重复参数：profile 的划分与显式指定、请用户通过网页登录并在聊天中不索要密码、凭据库授权提示的处理、下载—修改—diff/预览—带 revision 提交的编辑流程、冲突后的合并、`action-api` 的用法、错误码与应对。参数以 `ipe --help` 为准。
    Why：指南与 CLI 同版本，参数和错误码不会对不上。
19. README 面向人类，只讲卖点，并给出一句可以直接转发给 agent 的安装请求，链接指向 `packages/cli/INSTALL.md`。INSTALL.md 面向 agent（英文）：检查环境、`npm i -g` 安装（不想全局安装就改用 `npx -y @inpageedit/cli`）、向用户确认 API 地址后后台发起网页登录、用 `whoami` 确认，再引导 agent 读 `ipe skill`，最后是故障排查。命令参考不写进文档。
    Why：用户的安装成本降到转发一句话；用法以 `ipe --help` 和 `ipe skill` 为准，文档里不再维护第二份。

## 验收

- 用户从终端或网页保存账号后，新进程可以使用对应 profile。切换默认 profile 后，显式指定仍定位到原身份。
- 网页配置无需通过聊天、命令参数或日志传递密码。验证失败时用户可重试。
- 连续调用复用同一 profile 的会话。会话失效后自动续登，网络失败时写入请求只发送一次。
- agent 可以检索页面、获取源码和 revision ID、更新该 revision 或创建新页。编辑冲突和身份变化导致写入失败。
- 通用 GET、POST 表单、带附件的 multipart 请求均能带着 profile 身份发送。移动和上传复用 CSRF 获取逻辑，反馈实际结果及 API 警告。
- 不配置 profile 时可以用 `--api` 匿名读取公开 Wiki 的页面和搜索结果。
- 凭据库授权窗口未处理时，命令给出提示并在超时后退出。
- 能只读取和只编辑某一段，其他段落不变。
- `page get --out` 写出的文件与线上源码逐字节一致，改完后 `page diff` 显示的正是改动，`page preview` 能指出缺失模板和红链。
- `ipe skill` 输出与包内指南一致，`npm pack` 的产物包含 `dist`、`assets` 和指南。
