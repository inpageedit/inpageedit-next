# InPageEdit CLI

## 目标

让 agent 在终端以明确的 Wiki 和 bot 身份读取、创建及编辑 MediaWiki 页面。首次配置和凭据更新由用户直接完成。

## 范围

- 独立的 `@inpageedit/cli` 包提供 `ipe` 命令，使用 `wiki-saikou` 的 Node 客户端。IPE 浏览器核心的拆分留待后续。
- 支持 profile 列表及默认 profile 切换、身份查询、页面搜索、读取源码、创建、覆盖编辑、移动、上传本地文件以及通用 Action API 请求。

## 决策

1. 每个 profile 存放一个明确的 Action API 地址和 MediaWiki 账号。默认 profile 用于交互，`--profile` 为当次命令指定身份，便于 agent 并行操作。
2. 终端隐藏输入与一次性本地网页使用同一种 MediaWiki Bot Password。agent 可以预填 profile 名称、API 地址与 Bot Password 登录名。网页说明如何在 `Special:BotPasswords` 获取这两项，用户点击保存后 CLI 验证身份并保存 profile。
3. 配置目录默认为 `~/.config/inpageedit/`，可用 `IPE_CONFIG_DIR` 覆盖。Profile 文件保存 API 地址和账号信息。Bot Password 存入 macOS 钥匙串、Windows 凭据管理器或 Linux Secret Service。密码输入经过用户的终端或浏览器直接交给 CLI，命令行参数、输出和配置文件只处理非秘密数据。
4. 登录网页仅监听 loopback，采用随机会话路径，保存后关闭。每个 profile 在系统凭据库缓存独立的登录 Cookie，供不同 CLI 进程复用。Wiki 操作通过 `assert=user` 和 `assertuser` 校验身份。缓存缺失或登录状态被服务端拒绝时，用已保存的 Bot Password 登录一次。只有服务端在执行操作前明确拒绝认证或读权限时，才用新会话重试原操作。替换内容必须带原 revision ID，创建使用 MediaWiki 的 create-only 约束。
5. `--json` 在标准输出返回结果，在标准错误返回可识别的错误码。缺少或失效的凭据返回 `login_required` 和用户可运行的登录命令。

6. `action-api` 支持 GET、POST、重复的 `--query key=value` 和 `--form key=value`、`--form field=@path` 本地附件以及从 JSON 文件或 stdin 读取的 `--body` 字段。CLI 向当前 profile 的 API 发送请求，设置身份断言，并按 `--token csrf` 获取令牌。成功响应保留 MediaWiki JSON 数据结构。
7. `page move` 要求理由，默认保留重定向，可显式控制讨论页和重定向。讨论页移动失败时返回 Wiki 的警告。
8. `file upload` 默认使用本地文件名，支持指定 Wiki 文件名、摘要和描述文件。上传警告通过非零退出码与结构化错误返回，用户可以用 `--ignore-warnings` 确认继续。

## 验收

- 用户从终端或网页保存账号后，新进程可以使用对应 profile。切换默认 profile 后，显式指定仍定位到原身份。
- 网页配置无需通过聊天、命令参数或日志传递密码。验证失败时用户可重试。
- 连续调用复用同一 profile 的会话。会话失效后自动续登，网络失败时写入请求只发送一次。
- agent 可以检索页面、获取源码和 revision ID、更新该 revision 或创建新页。编辑冲突和身份变化导致写入失败。
- 通用 GET、POST 表单、带附件的 multipart 请求均能带着 profile 身份发送。移动和上传复用 CSRF 获取逻辑，反馈实际结果及 API 警告。
